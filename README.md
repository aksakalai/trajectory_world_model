# Trajectory World Model

This repository documents a personal experiment in action-conditioned visual
prediction. The project uses a custom Unreal Engine simulator to generate
first-person sequences containing player movement, camera motion, projectile
throws, a rendered projectile trajectory, and a Ready/Cooldown crosshair state.

The current dataset contains **3.38 million frames**. Dataset preparation and
factorized-autoencoder training are complete. The recurrent world model is the
next step and is still a work in progress.

## Dataset

The data was generated entirely in a custom Unreal Engine environment. Each
episode is a temporally ordered first-person sequence with aligned control
inputs and simulator metadata. The recorded controls cover movement, camera
rotation, and projectile requests, allowing future states to be paired with
the action that caused each transition.

The collection uses several mission families to create more varied motion,
camera behavior, object interactions, and trajectory changes:

- **Semi-Markov exploration:** mixed movement, camera, and action sequences
  sampled over time.
- **Object viewing:** approaching, observing, orbiting, or passing arena
  objects such as the hoop, pyramid, ramp, rectangle, and sphere.
- **Ramp traversal:** uphill and downhill traversal using centered and
  diagonal paths with different facing directions.
- **Hoop passage:** crossing the hoop from either direction along centered or
  oblique paths.
- **Contact and recovery:** approaching arena geometry and then recovering
  with varied movement patterns.
- **Static no-input segments:** stationary reference sequences that help
  represent cases where the scene should remain stable.

The split is grouped by episode: frames from one episode never appear in more
than one partition. This avoids evaluating on neighboring frames from a
sequence that was already used for training.

The dataset itself is **not public yet**. I plan to publish it after the files,
metadata, and usage notes have been packaged into a form that is practical for
others to use. There is no fixed release date at this stage.

## Factorized autoencoder

The completed autoencoder converts each `384 x 384` RGB frame into three
separate state components:

- a scene latent with shape `8 x 48 x 48`;
- a trajectory latent with shape `1 x 96 x 96`;
- one deterministic scalar representing the crosshair's Ready/Cooldown state.

The scene and trajectory branches use independent RGB encoders. Their decoders
are also isolated: the scene latent reconstructs the scene, the trajectory
latent reconstructs the trajectory mask, and the crosshair is rendered from
its scalar state. The resulting model contains **196,861 trainable
parameters** and uses **27,648 learned spatial latent values per frame**.

The final model was trained on all **3,043,394 training frames** using four
GPUs. On the held-out validation set, the training evaluation recorded:

| Metric | Result |
| --- | ---: |
| Reconstructed RGB L1 | 0.00463 |
| Trajectory precision | 0.9970 |
| Trajectory recall | 0.9197 |
| Trajectory F1 | 0.9568 |
| Trajectory IoU | 0.9171 |
| Crosshair pixel mismatches | 0 |

The autoencoder training code, configuration, and reconstruction examples will
be added to this repository along with image and video comparisons.

## What comes next

I am currently working on the action-conditioned recurrent world model. Its
goal is to predict the next factorized state from the current state, the
current control input, and recurrent memory. Longer predictions can then be
generated by feeding predicted latent states back into the model without
decoding and re-encoding an image at every step.

World-model training is not presented here as a completed result. It is the
active, experimental part of the project, and the design may change as the
next-state and multi-step rollout behavior is tested.
